## 3. Calibration sample size (SYNTHETIC)

A measured router is only as good as the sample it was fitted on. Each row fits the preference table on the first N tasks and asks how many of the 4 categories it gets right relative to the full 200-task trace.

| calibration tasks | sessions burned (2 arms) | categories ranked correctly |
|---|---|---|
| 10 | 20 | 1/4 |
| 25 | 50 | 3/4 |
| 50 | 100 | 4/4 |
| 100 | 200 | 4/4 |
| 200 | 400 | 4/4 |

This is the number worth arguing about. If the table only stabilises after hundreds of paired runs, a headroom heuristic is the right default until someone pays for the calibration.

> SYNTHETIC. Every number above is replayed from `synthetic-v1.jsonl`, generated by `crewbench/simulate.py` from invented priors. The ranking of backends and of policies is a property of those priors, not evidence about Claude Code or Codex. Swap in real observations with `--runner crew`.
